IMPLEMENTED
- Small identity, TLS evidence, endpoint, lifecycle, authentication and cached
read-only retrieval interfaces. No concrete I/O/security adapter or production DI.
- AuthenticatedTlsPeer is opaque/private-constructor, with no issuer or factory.
Synthetic metadata/booleans/hashes cannot create real evidence. DisabledTlsBoundary
always denies/native-proof-required and never calls a snapshot source.
- OFF/configured/eligible/stopped/shutdown planning lifecycle; restart OFF,
shutdown terminal, no socket/start method. Explicit data-only limits, wide integer
budget sum, timeout/cancellation metadata, no approved policy defaults.
- Synthetic identity session checks exact canonical private IPv4/ULA, IP SAN
type/value, endpoint port, chain/anchor digest metadata, SPKI, validity, path/EKU,
revoked trust and monotonic/UTC/boot confidence. Failure latches.
- Atomic commit/flush credential model with issuance, rotation, revoke, scopes,
expiry, bounded metadata/label history, serialization and uncertain acknowledgments.
No actual credential/token issuance or native/disk storage.
- Every restored ledger is RESTART_LOCKED, with no unlock/recovery API. Current
session failures/unknown writes deny all. Lost acknowledgment/crash closes it.
A fake new-empty-session constructor argument is NOT a production recovery gate.
- Canonical v1 schema/example/D3.2 fixture bytes unchanged. New shared fixture set:
46 identity traces,12 credential traces,9 freshness steps,9 malformed byte cases.
Digest manifests and identical expected decisions executed independently in C#/Kotlin.
- Strict snapshot readers now reject malformed UTF8, negative-zero and other
noncanonical revision forms, and unpaired surrogate escapes consistently.
No lossy Android adapter, timestamp invention or demo/live promotion.
- Branch-scoped safe Windows CI selection and script, preserving original tests,
assertions and ordinary test.ps1 for other branches. No runtime dependencies added.

RISKS / HARD BLOCKERS / D3.3B QUESTIONS
Synthetic path/chain/EKU/hash/clock metadata is untrusted and cannot replace actual
platform evidence. Future native issuer must bind validated immutable identity to
connection, trust generation, endpoint, clock/boot and credential lifecycle.
Default-off eligibility opens nothing. Limits/cancellation are not enforced sockets.
Locks serialize fake read/revoke decisions, not a future network response write.

Native persistence anti-rollback and durable revocation/restart recovery are NOT
established. DPAPI/Keystore confidentiality alone cannot identify the latest image.
Restored credentials must remain blocked until a separately approved durable model
is proven; there is no fallback. Bootstrap/pairing, QR format, clock authority,
port/interface, budgets and lifetime proposals remain owner decisions.

Intended future stacks: isolated Kestrel/.NET TLS with separately proven ephemeral
identity lifecycle; Android per-PC HttpsURLConnection/SSLSocketFactory with narrow
anchor and normal platform chain/hostname verification plus exact IP SAN/SPKI.
No native adapter/dependency/handshake implemented here. No trust-all, CN/DNS alias
fallback, pin-only bypass, implicit TOFU, HTTP fallback or silent trust reset.
Existing key-protection requirements were NOT weakened to accept a candidate
exportable identity; policy conflict requires separate owner decision.

D3.3B needs separate reviewed plan/approval: supported OS/API/flags, no named-key
side effects, ownership/disposal, chain/EKU/time/SAN/SPKI enforcement, narrow anchor,
connection binding, allowed listening/handshake scope and port/interface, cleanup
ownership, durable revocation/anti-rollback, clock/boot authority, real response-
commit races and explicit negative cases. DPAPI/Keystore/native persistence/
physical devices each require explicit scope. No old IDs/resources may be reused.

Recommendation: GO only for owner source review; NO-GO for automatic D3.3B native
execution. Stage safety criterion exception must be reviewed, not hidden by passes.
Rollback: keep these feature PRs unmerged, or owner-reviewed revert of just D3.3A
commits. No key/store/journal cleanup or destructive repository operation.
Both repositories separate; preserve unrelated/untracked files/assets/recovery.
