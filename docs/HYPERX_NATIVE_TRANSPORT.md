# Stage 4.0F: supervised manual HyperX transport

## What is enabled

The tray has a functioning **manual-only**, session-acknowledged HyperX query path. It is disabled on startup. After the operator accepts the interference/ambiguity warning, a query-free preflight must observe normal exit of a simulated helper and explicit Job termination/exit of a simulated stalled helper. No HID API is used by either simulation. The button is enabled only with opt-in, exactly one metadata-validated receiver, successful preflight and no failure latch. Missing helper, unavailable Job features/access, failed preflight, uncertain process state or a previous failed query cannot bypass these gates.

Production queries support **NGENUITY observed running only**. Both parent and helper check process names; unknown state or no observed NGENUITY refuses the concurrent path. This is an observation/heuristic, not a guarantee about every helper or a lock against process changes. The standalone POC's closed-app mode still requires its own closure acknowledgement/process guard. There is no implicit closed-app fallback or mixed acknowledgement.

A successful result is always **Candidate (Ambiguous)**, with observation time/source, never ConfirmedFresh. Receiver detection does not assert headset connectivity. A new request is not caused by startup, Refresh, reconnect, opening/hiding the panel or completing preflight. There is no retry, queue drain, poll timer, feature/initializer command, permission escalation, service/driver change or audio adjustment.

## Architecture decision and native lifetime review

The tray does not load the native HID transport assembly. `HyperXHelperTransport` supervises a fixed, installed `hyperx-helper/PeripheralBatteryCompanion.HyperXHelper.exe`, a production-owned self-contained component. It never shells out to a PowerShell script, dotnet, command interpreter or diagnostic POC executable. `HyperXNative` contains the existing audited POC transport; the POC and helper share it rather than maintaining unsafe copies. `HyperXHelperProtocol` holds only bounded JSON and pure fixed-packet validation and can be loaded by the parent safely.

The in-process design was rejected for the tray: CancelIoEx is a cancellation request, not proof of native completion. The POC retains a session, SafeFileHandle, ThreadPoolBoundHandle, pinned buffer and OVERLAPPED allocation until API return, IOCP completion and cancellation-call leases finish. That protects ordinary cancellation races, but a defective/non-completing driver can retain the entire object graph. A long-running tray must not free it on timeout or accumulate such sessions.

The chosen containment sequence is:

1. Create a non-inheritable unnamed Job with KILL_ON_JOB_CLOSE, active-process limit 1, and no breakaway. Three private inherited pipe ends are explicitly listed; the parent ends and Job handle are not inherited.
2. Create the fixed executable **suspended**, using STARTUPINFOEX / PROC_THREAD_ATTRIBUTE_JOB_LIST plus HANDLE_LIST. Job assignment is atomic with creation, not a later Process.Start/Assign window. Verify membership, establish owned process/pipe tracking and then resume. Any failure stays unarmed and fails closed; a failed membership check is terminated using the exact retained process handle while still suspended, there is no uncontained-process fallback.
3. Require a versioned ready frame with matching per-invocation nonce/mode and a bounded build identifier. Only then send a single explicitly risk-acknowledged Start command. Native execution cannot begin before this arm. Default/invalid helper arguments, simulation modes, missing/invalid acknowledgement, wrong nonce or malformed input cannot start native work.
4. The helper rechecks NGENUITY and exact metadata, acquires the compatibility semaphore, pre-arms one 62-byte read and uses the sole verified output buffer. Actual read-handle capabilities are rechecked. Exactly FF13:0001, input/output 62/62 and feature 0 are accepted for VID 03F0/PID 05B7/MI_03/COL01. Access remains shared GENERIC_READ/OVERLAPPED, never exclusive/broader fallback.
5. Validate the 62-byte input, 66/89 header and percentage 0–100. Bytes 2/3 remain unknown. Parent and helper share the same pure request/validation rules. No invalid input is displayed as a battery value.
6. Dispose/cancel native work without freeing incomplete allocations. The helper records native cleanup completion separately. The parent accepts a candidate only after a valid result **and observed normal process exit code 0**. Forced termination, crash, malformed IPC, missing exit or uncertainty cannot promote a candidate, even when bytes had looked valid.

The parent uses a machine-wide named semaphore for native child ownership, plus a process-wide non-queued gate. The parent retains the global lease until observed child exit, including quarantine. The rebuilt POC also takes this global entry gate; the helper retains the original session-local gate for compatibility with older POCs in the same session. These coordinate cooperating components, not NGENUITY or arbitrary third-party software. Do not run old diagnostic binaries alongside a production test; historical binaries in other sessions cannot be assumed to participate in the new global gate. Access denial on a named object fails closed without elevation.

### Timeout, cancellation and incomplete exit

The native exchange deadline remains **3 seconds**, beginning after metadata/open setup and covering output plus one input. It is not 3 seconds per operation or a total process/startup deadline. Parent startup/ready budget is 5 seconds, result budget 8 seconds (including setup), and teardown uses bounded cooperative stop/exit waits followed by at most one explicit TerminateJobObject request and a bounded exit observation. The provider's 20-second invocation guard covers the supervisor envelope. These are scheduling budgets, not hard real-time guarantees for arbitrary kernel failure.

Cancellation sends one Cancel control message and closes stdin; the helper requests I/O cancellation. Normal completion closes stdin to let the helper finish its control reader. Console input can synchronize async reads, so blocking console/control and execution delegates run on owned helper workers; they cannot stop the parent's UI message loop. The parent supervisor is also dispatched off the UI thread. A bounded 30-second no-HID hold simulation exists only to test forced process exit; it never opens a device.

If graceful exit does not occur, termination is **reported**, not hidden. Windows documents that TerminateProcess stops all threads and requests I/O cancellation, and that the process cannot exit until pending I/O completes or is cancelled. TerminateJobObject has those semantics for its member processes. Observed process exit is therefore the process-isolation completion boundary under the Windows/driver contract; the parent never frees or reuses a child's HID buffer.

A driver can still delay termination indefinitely. If exit is not observed within the wait budget, the result is failed/cleanup-unconfirmed, querying latches off, and the child/Job/pipes/global lease remain rooted in an owned registry. An Exited event releases them later; there is no infinite waiter, polling reaper, abandoned worker or forced buffer release. Parent process exit closes the non-inherited Job handle and requests termination again via KILL_ON_JOB_CLOSE. Windows may retain kernel state for a defective driver; **no finite kernel reclamation guarantee or successful cleanup is claimed**. No candidate is accepted from that path. This OS contract and live no-HID process preflight support enabling the isolated path; they do not prove receiver-driver compatibility or native cancellation behavior on hardware.

### Cancellation race corrected during implementation

The existing timeout test exposed a real coordinator ordering race: a timer could unblock WaitAsync before earlier I/O token callbacks had run; CancelAsync on that already-cancelled timer source did not drain them, and disposal could unregister the read cancellation callback. The coordinator now uses a separate owned I/O cancellation source and awaits its CancelAsync before disposing the session. Deadline waiters keep the original timer source. The failing assertion was retained, no sleep/retry added, and the focused plus full suites passed after the correction. Pending native storage still waits for actual completion, not merely callbacks being invoked.

## IPC and sanitized diagnostics

Private stdin/stdout carry one ready frame, one Start and one result; Cancel is the only other control. Frames are at most 4096 characters, with strict schema/depth, version, mode, nonce and enum validation; incoming battery data is at most 62 bytes and revalidated by the parent. No arbitrary target, report, executable, timeout or device path is accepted. Untrusted malformed frames/exception messages/stderr are never copied into diagnostics. Late task faults are observed and late/unconfirmed children retain explicit ownership. The factory also owns a pending process-creation task; a late cancelled creation is terminated unarmed, and its state is never mislabeled as successful startup/cleanup.

The copied summary includes helper build/revision, protocol/mode, fixed target/access/share flags, NGENUITY observation, capability/shared-open outcomes, numeric stage errors, arm/request/output confirmation, validation/header/candidate/time, ambiguity, elapsed times, native cleanup versus process-exit outcome, termination requested and unconfirmed cleanup. Arm attempted is a submission intent, not proof of USB delivery. Unknown delivery is explicit after IPC/process failure. Serial numbers, full HID paths, arbitrary traffic and private paths are not logged. The helper's assembly build identifier records the source revision at compilation; packaging does not fabricate a future commit ID.

## UI lifecycle and failure recovery

- Query stays disabled before acknowledgement/preflight/receiver gates. Declining acknowledgement starts no helper. Opting in runs **simulations only**, never a battery request. Opt-out/restart defaults off; opt-in does not send an automatic first query.
- Query is non-queued/single-flight. While preflight/query is running, the checkbox/query control is disabled and Cancel is available. Refresh remains G915 refresh plus HyperX metadata only.
- Cancel or Exit Application requests cancellation and waits for bounded supervised teardown. Closing/Escape/tray dismissal only hides the panel; an already requested bounded shot may finish and update the hidden view, without another query or focus activation. Use Cancel or Exit to stop it.
- Timeout, cancellation, invalid/buffered response, access denial, unavailable target or process/supervision failure stops subsequent query attempts for that provider session. Toggling opt-in does not clear the latch. Previous candidate data becomes explicitly Stale; no value is recycled as fresh on reconnect.
- On audio disruption, NGENUITY freeze, receiver reset or unexpected activity: Cancel, stop and preserve the sanitized summary. Do not repeat, elevate, restart services or switch drivers as a workaround. Confirm recovery separately. A later restart/opt-in is a new deliberate operation and does not constitute approval for another physical test.

## Testing, packaging and hardware gate

The portable suite uses fake child/process/query boundaries; no USB API is invoked. Windows tests separately exercise real Job/pipe/process operations with a wrapper that **rejects NativeOneShot** and only permits Simulate/SimulateHold, plus UI control/layout checks. The Windows workflow runs those tests through the unchanged test.ps1 runner. Cloud execution on Linux does not establish those Windows results; see the implementation report for observed counts.

Release and Debug publish must contain the `hyperx-helper` folder and its self-contained .NET runtime. Main depends only on Core/metadata/pure protocol; native HID assembly is isolated under the helper folder. `scripts/Test-HyperXArtifact.ps1` checks required files, dependency separation and absence of diagnostics/private captures, without executing either app. The existing publisher invokes that check before zipping. Visual Studio builds copy the helper folder for F5. Distribute the entire ZIP/folder, not just the tray EXE. Missing components leave querying disabled.

**No physical query was authorized or run during implementation.** Before one separately approved test: review this ADR/code and Windows no-HID CI results, inspect the package, keep NGENUITY/helper normally running with one receiver/headset, note its displayed value/audio behavior, and ensure no standalone POC is active. After explicit owner approval, launch the reviewed artifact, opt in, verify query-free preflight succeeds, and click Query **once**. Record candidate/ambiguity/time, the complete sanitized cleanup summary and NGENUITY/audio state; then stop and await review. A matching percentage is consistency, not unique correlation/freshness. Do not repeat on failure. Any USBPcap follow-up or second attempt needs separate approval. No active PowerShell test command is supplied as an instruction to execute now.
