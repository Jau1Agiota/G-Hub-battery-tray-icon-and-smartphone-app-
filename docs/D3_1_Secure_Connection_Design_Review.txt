THREAT MODEL
Same-LAN attacker can scan, spoof DNS/ARP, redirect, inject, record or drop traffic.
TLS without authenticated bootstrap does not prevent initial interception.
Rogue phone gets no data or enrollment outside explicit local approval.
Rogue PC cannot substitute a different SAN/certificate/SPKI or induce trust-on-first-
network-use. Replay needs one-use pairing, bounded sessions and publication checks.
Stolen bearer tokens remain usable until expiry/revocation; nonces do not make
a bearer credential sender-bound. Protect, scope, expire and revoke them.
Stolen QR may race during the window; local PC confirmation reduces mistaken
enrollment but cannot cure fully compromised bootstrap plus fooled user.
Accidental exposure requires exact interface/Private profile/port and default OFF.
Downgrade to HTTP, trust-all, hostname bypass, weaker protocol or pin reset is denied.
Credential loss disables service and requires explicit re-pair, not silent recovery.
DoS is bounded by admission, time/size limits and no unauthenticated expensive work;
availability cannot be guaranteed against hostile Wi-Fi/network peers.

Assume patched supported OS/runtime, uncompromised owner accounts and authentic
local screen/camera exchange. Same-user malware, administrator/root compromise,
stolen unlocked devices, supply-chain compromise, traffic analysis, router
availability and physical battery accuracy are non-goals. OS storage protection
is not proof against a compromised live process.

ADR 1 — IDENTITY WITHOUT NAMED PERSISTENT KEY PROVISIONING
Proposed preferred option: supported .NET ephemeral certificate/key creation,
deliberately exportable in process, with DPAPI CurrentUser-protected private-key
envelope on disk. Load using explicit supported ephemeral import semantics
(for example applicable X509CertificateLoader + EphemeralKeySet), never
PersistKeySet or implicit named-key defaults. This is a candidate requiring
API/platform review, not a verified native recipe. No nonexportability, hardware
protection or complete managed-memory erasure claim.

Before ANY native provisioning, establish exact supported APIs/flags, provider
lifetime, certificate usage and TLS interoperability; demonstrate import/create
does not require persistent named provider objects. Review documented semantics
plus separately authorized isolated Windows validation. Observing no key afterward
alone is not universal proof. Any ambiguous side effect => NO-GO; no best-effort
native cleanup, recovery or adoption.

Envelope: local owner-only nonreparse directory, explicit ACL validation,
create-new protected temporary file, durable flush and atomic replacement under
single-owner local provisioning lock. Only protected bytes reach disk.
Unknown ACL/path is rejected, not automatically repaired. Crash may leave a
protected file orphan; no recovery/adoption by name alone. Missing/corrupt envelope
or DPAPI loss after account/machine migration disables listener and forces
owner-approved fresh identity/re-pairing. No plaintext PFX/password file; any
container password is not the storage security boundary.

Alternatives:
- Session-only ephemeral identity: avoids persistent envelope but requires pairing
each restart; safe usability fallback if separately approved.
- Owner-selected pre-existing certificate: no app provisioning, but exact SAN,
SPKI, validity, EKU/private-key access/lifetime must be reviewed; no broad discovery,
adoption or permission repair of unrelated keys.
- OS-managed persisted/nonexportable CNG key: potential isolation benefits, but
ownership/atomicity unresolved; excluded from D3.
- Public/custom CA enrollment: broader trust/distribution burden, unnecessary here.
B1 export success proves neither persisted policy nor nonexportability.
Option2 remains native NO-GO; retired and preview IDs must not run, be reused,
inspected, adopted or cleaned. No dependency on that harness.

ADR 2 — TLS IDENTITY
HTTPS only; minimum TLS1.2, prefer TLS1.3; no TLS0-RTT, HTTP fallback or redirects.
Dedicated per-PC Android client, no system-wide trust modification.
QR transfers exact leaf certificate as narrowly scoped trust anchor, SHA256 SPKI
pin, exact endpoint/SAN and protocol version. Validate X.509 path to that anchor,
validity, constraints/server-auth usage AND normal exact endpoint hostname/SAN
verification AND SPKI hash. No trust-all manager, pin-only chain bypass or CN-only
fallback. If narrow-anchor integration cannot work without bypasses, STOP.

Inherit existing conservative prerequisites: assigned RFC1918 IPv4 or IPv6 ULA,
explicit unprivileged port1024..65535, exact deliberate interface, Private profile.
No default port is approved here; no wildcard/public/link-local/scoped/mapped
address. IP endpoints require an exact IP SAN, not DNS-string comparison.
DNS support would require separately approved exact DNS SAN, no wildcard.
Changed address/SAN needs owner review/reprovisioning, never weakened validation.
Propose leaf90-day lifetime, warn14 days before expiry; values require approval.
Bad clock/expiry blocks connection. A system-trusted wrong pin is rejected.

PAIRING SEQUENCE — FIRST USE
1. PC owner explicitly approves interface/address/port and exposure warning.
Listener remains OFF until identity, storage and profile gates pass. App never
changes firewall rules; any dedicated manual rule requires separate approval.
2. Owner opens proposed120-second pairing window. Generate CSPRNG256-bit one-use
secret and opaque session only then. Display local QR with endpoint, certificate,
SAN, pin, version, session, expiry and secret. No URL query secret, logs, clipboard
or telemetry. Short numeric code alone is not an acceptable secret.
3. Phone scans real PC screen, bounds/parses locally and asks user confirmation.
Validate anchored TLS + SAN + pin BEFORE sending any secret.
4. POST secret in protected body, phone random nonce and bounded untrusted label.
PC verifies secret hash, monotonic expiry and admission limits; atomically locks
session to first valid attempt/flow. Concurrent/repeated submissions denied.
5. PC and phone show same transcript-bound comparison code, derived using a
domain-separated hash of session/endpoint/pin/phone nonce/server nonce.
Propose eight decimal digits and one attempt/session; exact encoding needs D3.3
review. Comparison code is an aid, not a replacement for high-entropy QR secret.
Owner confirms matching code on the phone being held. No unattended approval.
6. After approval, atomically persist per-device credential ID, token hash verifier,
snapshot.read scope, expiry/revocation; issue random256-bit bearer token via the
same verified TLS flow. Proposed maximum lifetime30 days; no refresh token.
Phone encrypts token under Android Keystore AES-GCM key, unique nonce/tag and
authenticated PC/pin/credential metadata; ciphertext in private storage.
7. Consume secret, close window. Clear owned buffers where supported; managed/OS
copy erasure is not guaranteed. Lost response/crash => no automatic reissuance or
secret recovery; show possible orphan enrollment for local revocation and start
a new explicitly approved window.

Active-LAN resistance: authentic screen QR supplies identity and secret before
network use. Attacker substitution fails certificate/SAN/pin validation; relaying
genuine TLS reveals no token. QR theft/phishing remains residual risk.
Numeric-only pairing would need separately vetted PAKE/library review; do not
invent a custom challenge-response protocol.

RECONNECT
Load approved trust/endpoint and unseal token; perform identical TLS validation,
then Authorization: Bearer, never query token. Server checks scope, verifier,
expiry and revocation on every request. No snapshot in unauthorized response.
CONNECTED requires authenticated valid nonsynthetic snapshot, not TLS alone.
Disconnect => offline/stale with separate last-known data, no invented observation.
Monotonic active-session budgets supplement UTC expiry; startup clock rollback
must deny uncertain validity. Persistent trusted-time strategy remains unresolved;
no absolute trustworthy-clock claim.

ROTATION
Owner initiates new identity meeting the same lifecycle gates while old identity
is valid. Prefer explicit fresh QR + confirmation per new certificate/pin.
No silent learning after mismatch; new SAN also requires bootstrap review.
Any dual-pin/anchor overlap must be exact, visible and bounded by explicit approval.
Expired/compromised old identity requires local re-pair; no network-only recovery.
Retire old credentials, close connections and remove app-owned protected envelopes
only under separately reviewed file lifecycle policy; never old CNG evidence.

REVOCATION
PC local owner revokes selected opaque credential; durable record before success,
invalidate sessions and recheck auth before response commit. Failed durable
revocation => stop listener, deny all. No remote admin/revoke route.
Phone Forget deletes local token/trust; PC revocation separately required for
possible leakage. Lost phone => local PC revoke. Credential store loss/reset =>
listener OFF, invalidate all pairings, explicit fresh bootstrap, no silent trust.

NETWORK AND RESOURCE POLICY
Default OFF; fresh local owner consent every process restart. Persisted desired ON
does not restore approval. Existing monitoring consent/startup/cadence unaffected.
No discovery, UPnP, broadcast, public routing or cloud relay.
Recheck profile/interface/address, identity and storage on events and admission;
failed/unknown observation latches OFF, closes listener and cancels requests.
Recheck before data delivery; event detection races/latency remain a residual risk.

Proposed review budgets:4 parallel handshakes,8 active requests,16KiB headers,
8KiB pairing body,64KiB snapshot, JSON depth16,5-second handshake/header and
10-second request deadline; bounded queues. Pairing: one pending approval,
five failures/window globally then close; per-source plus global admission.
Snapshot: one outstanding request/credential, max one per5 seconds; propose
foreground30-second polling, bounded backoff, pause background. Not implemented
or performance-verified. No browser/CORS access or remote admin commands.
Auth before serialization, no-store response, no automatic redirects. Constrain
client proxy routing so credentials never migrate to a different origin.
Logs omit tokens, QR, headers/body, paths, raw reports and device identifiers.

Disable/shutdown: stop accepts, cancel/drain bounded work, close connections,
dispose ephemeral resources and clear owned buffers; unconfirmed close is safety
stop, not success. Never change monitor schedule or clean experiment journals.
