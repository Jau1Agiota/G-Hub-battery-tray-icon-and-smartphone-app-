2. DECISION SUMMARY / BLOCKERS

A. Retain a NONEXPORTABLE test-only candidate: explicit CngKey.Create with null
name, Microsoft Software KSP, ExportPolicy=None, Signing usage and reviewed flags.
No DPAPI/PFX/exportable substitution. [D] Null name is documented ephemeral;
None is documented not exportable. [U] Request/metadata is not behavioral proof.

B. Reject ECDsa.Create(nistP256) as the selected W1 factory. [I] In v10.0.0 Windows
it wraps ECDsaCng(curve); CngAlgorithmCore.GetOrGenerateKey explicitly requests
AllowPlaintextExport. The public ECDsa factory contract provides no nonexportability
guarantee. Ephemeral does not mean nonexportable. Do not silently repair that key's
policy after creation, retry with another provider or reuse it as the candidate.

C. Exclude CreateSelfSigned / public CopyWithPrivateKey from the proposed no-export
path. [I] CreateSelfSigned calls CopyWithPrivateKey. Windows ECDSA association first
tries a persisted-key association; its helper returns null for empty KeyName, then
the public path calls ExportParameters(true), imports a clone and associates that
clone. A nonexportable unnamed key would encounter an implicit export attempt.
This is forbidden even if the attempt fails. It can also violate the one-key budget
if export succeeds. No test may use failure of this path as an export probe.

D. Proposed W1 REVISION: separately owned unnamed nonexportable key plus a PUBLIC
test leaf signed with it using CertificateRequest.Create(issuerName, generator,
notBefore,notAfter,serialNumber). [D] This overload returns a certificate without
HasPrivateKey. [I] Its inspected path signs and loads public DER, without calling
CopyWithPrivateKey. The generator exports PUBLIC parameters only. This tests key /
public-leaf lifecycle, NOT a usable associated TLS server identity. It changes the
earlier W1 association objective and requires explicit owner agreement, not silent
substitution. No new native association API or internal/reflection workaround is
proposed for automatic implementation.

E. ACL blocker: [D] NCRYPT_SECURITY_DESCR_PROPERTY applies only to persistent keys.
Current-user scope (no MACHINE flag) is not proof of an owner-restricted key DACL.
No documented equivalent owner-DACL evidence for this unnamed key was established.
Propose only a TEST-ONLY exception: label ACL evidence NOT ESTABLISHED and never
invoke/satisfy LanApprovalSession. The production NonExportable AND
CurrentUserAclRestricted requirements remain unchanged. Owner must approve/reject
this explicit exception before any W1 request can be executable.

Recommendation: REVISE before submitting the original associated-certificate W1
approval request. A revised public-leaf-only request can be drafted after the owner
accepts that scope and the test-only ACL-evidence exception, and supplies the exact
runtime for source reconciliation. NO-GO to execution now. S0 is not proof that
production nonexportability, ACL protection, native cleanup or TLS works.

  Review criticality explicitly (candidate: SAN/EKU noncritical, KU/basic critical),
  no duplicate extension OIDs; constructor/extension work may call public-key/native
  encoding paths and belongs inside the future approved method, not discovery.

  CertificateRequest.Create(X500DistinguishedName issuerName,
  X509SignatureGenerator generator, DateTimeOffset notBefore, DateTimeOffset notAfter,

Expected leaf.HasPrivateKey=false. Public SPKI from the signer/certificate must
match, pin is SHA256 of DER SubjectPublicKeyInfo, NOT certificate fingerprint.

Internal CopyWithEphemeralKey uses CERT_NCRYPT_KEY_HANDLE_PROP_ID and ownership
transfer; it is NOT a public escape hatch or permission for reflection/new PInvoke.

K6 (PROPOSED REVISION): Create(issuerName,generator,notBefore,notAfter,serialSpan).
R13 performs DER encoding, generator.SignData -> ECDsa.SignData using existing key,
then X509CertificateLoader.LoadCertificate of encoded public DER; no K5 call in
the inspected path. R8 documents HasPrivateKey=false. One public cert context;
bounded public DER/signature buffers and public-parameter operations, no private
export/import. Use exactly this overload, not issuer-certificate overloads, which
may retrieve private keys from another certificate.

K7: X509Certificate2 public inspection/RawData and explicit
X509CertificateLoader.LoadCertificate(byte[] rawData), if separately budgeted.
Loading even public DER allocates native cert context; no store mutation by this
call alone. K6 already loads a context, so a second explicit load is unnecessary
and excluded from the minimal resource budget. No obsolete PFX constructor or
LoadPkcs12; EphemeralKeySet is not a magic protection flag for unrelated creation.

K8: GetECDsaPrivateKey(X509Certificate2).
R16/R17 can acquire/duplicate a handle, use provider metadata and reopen a named
key for persisted associations; provider/UI access may result. Returned ECDsa
must be disposed by its owner. For proposed public leaf it is expected absent;
do not call it in minimal W1 just to exercise a native getter. HasPrivateKey=false
is enough for its public-leaf objective; absence does not prove candidate cleanup.

K9: cleanup: dispose public leaf first, then ECDsaCng duplicate, then original
CngKey/provider references; release all optional public inspection wrappers too.
CertificateRequest/signature generator are not IDisposable owners of the key.
Never dispose an alias twice or use a disposed reference. [D] NCryptFreeObject
releases an object [R18]; .NET SafeHandle disposal is the wrapper mechanism.
Dispose returning/IsClosed is managed lifetime evidence, not an observed native
free-success receipt, no-leak proof or proof of no persistent side effects.
If the approval requires independently observed native release success, standard
public BCL disposal alone may be insufficient: report CleanupUnconfirmed/STOP;
do not add native instrumentation without another review/approval.

Normal exit: follow K9 even after partial failures, only for owned live references.
Abrupt termination: finally may not run; OS process-handle teardown is not an
application-observed cleanup result. No deliberate kill/crash subtest is included
in the minimal single shot. Any later crash test needs a new approval. Named or
store state survives ordinary handle release and is never speculatively cleaned.
On an exception, record only phase, exception category/HRESULT if available,
requested-versus-observed policy and ownership certainty; no private data/user
paths/raw handles. Unknown disposal/persistence => INCONCLUSIVE/STOP, preserve
evidence under its approved report policy, no retry, reopen, enumeration or adoption.
